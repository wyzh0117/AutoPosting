## Goal

Each `#favorites-list .fav-item` has an **打开原文** button that opens the original reader for that favorite, even when it is not the left-list focus. Title click still `togglePicked`. Toolbar `#open-original-btn` still uses `state.item`.

## Approach

- `renderFavorites` appends `button.fav-open-original` labeled `打开原文` after the summary. Click `preventDefault` + `stopPropagation` then `openOriginal(item)`. Title click unchanged (`togglePicked` only).
- `openOriginal(item)` uses `item || state.item`. Fetch `/api/original` with that `item_id`. Title copy uses the argument item, not `state.item`.
- Success path no longer requires left-list `state.item.item_id === itemId`, so a favorite that is not in the current hotspot list still fills the dialog.
- Toolbar listener is wrapped: `function () { openOriginal(); }` so the click event is not treated as `item`. `closeOriginal` unchanged.
- Toolbar `busy()` only when the opened id matches focused `state.item`, so a favorites-only open does not enable `#open-original-btn` with no focus.

Did **not** move `#picked-dock` or edit its `position:fixed` CSS. Did not call `selectHotspot` from the favorite button (optional in spec; would risk `clearHotspotSelection` → `closeOriginal`).
