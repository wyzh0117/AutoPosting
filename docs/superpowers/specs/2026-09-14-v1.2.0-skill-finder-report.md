# 1.2.0 Skill 查找器 — implementer report

Worktree: `/Users/youngi/Documents/MiniWork/AutoPosting` (no isolated worktree existed; implemented in the parent 1.1.3 tree). Version left at **1.1.3**. Live 8080 service not restarted.

## Root causes

1. **Image module looked empty.** `#skills-studio` / `#skills-gallery` already unhide on `body.lane-skills`, but the gallery had no empty state, sat below the article, and images stayed `[]` until a second click on `#skills-render-btn`. GitHub weekly’s 生成图片 lives in the left header; skills’ only controls were in the right pane with nothing queued.

2. **Search blocked the UI.** `find_skills` and `POST /api/skills/search` waited for decompose + search + `write_article` and returned `images: []`. There was no `on_event`, no `phase`, and no GET-poll progress, so the left list could not update incrementally and images could not start until the full package returned.

3. **Second similar search went to zero.** GitHub GET/search had no process cache; a 403/429/timeout in `fetch_skill_md` / `_try_get` was swallowed as “not a skill”. Previously accepted skills were not reused. Budget exhaustion did not clear `collected`, but overlapping queries re-paid the same HTTP and then dropped hits.

4. **Gap stages leaked everywhere.** Empty required stages set `gap: true` and stayed in `stages`, chips (`is-gap` · 缺口), article JSON, and `PACKAGE_ARTICLE.md` section 5.

## What changed

- `find_skills(..., on_event=, previous=, cancel=)` emits `stage` / `skill` / `skills_ready` / `article` (never `image`). Payload `phase` is `searching` | `skills_ready` | `error`. Coverage/article/UI stages are only those with ≥1 accepted skill.
- Process-local GitHub GET/search cache (TTL 15 min; hits skip `_FetchBudget`). Reuse last snapshot skills whose `source_id` still maps to a stage. Rate-limit on SKILL.md fetch is not a quality miss (`skill_path=SKILL.md` + stars/freshness/registry).
- `POST /api/skills/search` starts a background job, persists via `save_skill_finder`, returns immediately; JS polls `GET /api/skills`. AbortController / `{abort: true}` sets the cancel event. After `skills_ready`, `searchSkills` auto-calls `renderSkillImages()`; the button is retry. `skills_render` sets `phase=rendering` then `done` and streams images into the snapshot.
- Right pane: toolbar + `#skills-gallery` first (min-height, empty copy / queued tiles), article below. No `is-gap` chips.
