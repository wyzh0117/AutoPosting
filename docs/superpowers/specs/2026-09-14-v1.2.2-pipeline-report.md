# AutoPosting 1.2.2 — Skill Finder 7-step pipeline report

Agent A (pipeline). Did not bump version, restart 8080, write PATCH/archives, or commit.

## Root cause

1.2.1 `find_skills` was a single LLM `decompose_coverage` (title/theme/stages) then GitHub/web search then `write_article`. The snapshot had no `goal`, `chain`, `groups`, or frozen `progress` object, so the UI could not tell which of the seven work steps was running versus hung. Network budget was `MAX_FETCHES=40` / `FETCH_DEADLINE_SECONDS=45`, which aborted HTTP on a 45s wall clock. Search used only the first keyword per module. `skills_ready` fired before the article existed (1.2.1 poll then waited for `article.body`). Persist in `WebApp.skills_search` forced every non-terminal event `phase` to `"searching"`, which would have hidden the seven step names on `GET /api/skills`.

## Approach

Restructure `find_skills` into the frozen 7-step pipeline, still **at most two LLM completions** (plan JSON + article):

1. `understanding` / 理解需求 — emit progress, then one plan completion
2. `chain` / 还原生产链 — apply `chain` from the same JSON
3. `decompose` / 分解工作流 — apply 6–12 `stages`
4. `keywords` / 生成关键词 — `stages[].queries` (zh+en)
5. `search` / 查找 Skill — GitHub + web using those keywords; detail `正在检索：{module} · {keyword}` at least once per module
6. `group` / 还原分组 — `_filled_stages` + `groups`; empty modules omitted
7. `compose` / 组合工作流 — `write_article` as end-to-end workflow, then `article`, then `skills_ready`

Kept 1.2.1: quality gate, `SKILL_CAP=16`, 15 min GitHub cache, previous-snapshot reuse, no gap copy, stream `skill` events before images, article present before `skills_ready`. No `time.sleep` padding. `progress.elapsed_ms` is monotonic across events (bump at least +1 ms if the clock did not move). Network defaults `MAX_FETCHES=80`, `FETCH_DEADLINE_SECONDS=240`; injected values still cap HTTP only.

`decompose_coverage` now parses the plan object (`goal`, `chain`, `title`, `theme`, `stages`). Missing `chain` is synthesized from stage names so old fixtures still work.

Persist-only change in `WebApp.skills_search`: keep pipeline phases `understanding|chain|decompose|keywords|search|group|compose` instead of rewriting them to `searching`. Did not touch `INDEX_HTML`.
