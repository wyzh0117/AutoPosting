# AutoPosting 1.2.2 — Skill 查找器工作流 + 进度观感

Controller-owned patch. Two grok-4.6 implementers. Do **not** bump version, restart 8080, or write PATCH/archives.

## Goal

Skill 查找器按这条链工作，并让用户分得清「在干活」和「卡死」：

理解用户需求/目标 → 还原完成生产链条 → 工作流分解 → 按模块生成关键词 → 用关键词查找 skill → 按模块还原分组 → 组合成 end-to-end workflow。

同时：查找按钮「查找」两字必须同一行完整显示；全局等待条去掉难看的滑动 meter，中断（停止）行为不变。

## Current baseline (1.2.1)

- `find_skills` in `src/autoposting/skill_finder.py`: one LLM `decompose_coverage` (6–12 stages) → GitHub/web search → cap 16 → `write_article`.
- Network budget `MAX_FETCHES=40`, `FETCH_DEADLINE_SECONDS=45`.
- Streaming: `on_event` kinds `skill` / `skills_ready` / `article`; poll `GET /api/skills`; auto-render images after skills.
- Gaps omitted. GitHub cache 15 min. Reuse previous snapshot by stage id/name.
- Wait UI: `#wait-banner` `.wait-job` with spinner, title, detail, elapsed, **停止**, and `.wait-meter` sliding bar.
- Search row: `#skill-search-row` + `#skill-search-btn` text `查找`. Input `width:100%` plus flex causes the two characters to wrap/clip.

`find_skills` snapshot (and therefore `GET /api/skills` / persist) MUST include:

```json
{
  "query": "…",
  "goal": "一句话目标",
  "chain": [{"id": "c1", "name": "选题", "role": "入口"}],
  "title": "…",
  "theme": "…",
  "stages": [{"id": "…", "name": "…", "queries": ["…"], "required": true}],
  "skills": [],
  "groups": [{"stage_id": "…", "skill_ids": ["owner/repo"]}],
  "article": {"title": "", "body": ""},
  "images": [],
  "package_path": "",
  "phase": "understanding",
  "progress": {
    "step": "understanding",
    "label": "理解需求",
    "detail": "正在把输入收成可执行目标",
    "step_index": 1,
    "step_total": 7,
    "started_at": "ISO-8601",
    "elapsed_ms": 0
  }
}
```

### Seven steps (exact `step` / `label` / `phase` while searching)

| index | step | label | phase |
|---|---|---|---|
| 1 | understanding | 理解需求 | understanding |
| 2 | chain | 还原生产链 | chain |
| 3 | decompose | 分解工作流 | decompose |
| 4 | keywords | 生成关键词 | keywords |
| 5 | search | 查找 Skill | search |
| 6 | group | 还原分组 | group |
| 7 | compose | 组合工作流 | compose |

After compose: existing `skills_ready` (skills+article present) → UI may render images → `rendering` / `done` / `error`.

`on_event("progress", snapshot)` on every step change and during search at least once per module (detail MUST name the module and current keyword). Frontend treats missing `progress` as “查找中”.

## Pipeline (Agent A)

Keep: quality gate, SKILL_CAP=16, cache, reuse, gap hiding, streaming skills before images, article-before-`skills_ready` wait from 1.2.1, Python 3.11 stdlib only.

Change `find_skills`:

1. **理解需求** — LLM produces `goal` (and audience/deliverable if present). Emit progress step 1.
2. **还原生产链** — ordered chain, left→right shallow→deep, 0-to-deliverable. Emit step 2.
3. **工作流分解** — 6–12 modules (`stages`). Emit step 3.
4. **关键词** — each module 2–4 keywords (zh+en). Emit step 4. `stages[].queries` = those keywords.
5. **查找** — existing GitHub + web search using those keywords; emit skill events; progress detail `正在检索：{module} · {keyword}`.
6. **分组** — assign skills to modules; `_filled_stages`; `groups`. Empty modules omitted. Emit step 6.
7. **组合** — `write_article` as end-to-end workflow (see PACKAGE_ARTICLE). Emit step 7 then `article` then `skills_ready`.

LLM call count: **at most two** completions (plan JSON + article). Do **not** pad with sleep. You MAY parse one plan JSON into steps 1–4 and emit four progress events as fields are applied (no fake delays).
