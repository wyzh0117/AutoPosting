# 1.2.3 Task A — focus vs pick (bug) implementer report

## Root cause

Hotspot cards used two highlight systems that looked the same:

- Card-body click → `state.item` + `.hotspot-item.selected` (gold fill + glow + left bar). Used by generate only when `pickedIds` is empty.
- Title click → `state.pickedIds` + `.is-picked` (inset gold). Generate uses this set whenever any pick exists.

`selectHotspot` never toggled off. Re-clicking a focused card kept the gold. After favorites/title picks filled `pickedIds`, generate ignored the left focused card. User could not unfocus it.

## Approach

- Quieted `.hotspot-item.selected`: dropped gold fill (`rgba(196, 164, 106)` gradient) and `accent-glow`. Kept `::before` 3px left bar. `.is-picked` inset gold unchanged. A card may have both.
- Re-click of the already-focused card body (`state.item.item_id === item.item_id`) calls `clearHotspotSelection()` then returns. Title click still `stopPropagation` + `togglePicked` only; `.ht-star` still stops propagation as a sibling.
- `clearHotspotSelection` now strips `.selected` / `aria-pressed` on `#hotspot-list .hotspot-item` and sets `state.item = null`.
- After `selectHotspot` and `clearHotspotSelection`: `if (typeof renderPickedDock === "function") renderPickedDock();` (Agent B defines the function; missing is safe).
- `generate()` payload rule unchanged: `picked.length >= 1` → `item_ids`; else `item_id` from focused `state.item`.

Did **not** add `#picked-dock` or edit `renderPickedDock` body.
