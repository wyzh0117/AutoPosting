## 2. Coverage-search method (encode, do not one-shot 短剧)

Pipeline in `src/autoposting/skill_finder.py`:

1. LLM reads `docs/skill_finder/COVERAGE.md` + user query → JSON `{title, theme, stages:[{id,name,queries,required}]}` with 6–12 stages, 0-to-1, shallow to deep.
2. Search each stage via injectable fetchers:
   - GitHub repo search: `SKILL.md {terms}` using the existing GitHub GET helper pattern in `github_weekly.py` (`api.github.com/search/repositories`).
   - Web search: existing `search_web` for `{terms} SKILL.md site:github.com` and skill-registry phrases.
   - Optional known roots (best-effort, skip on HTTP error): `anthropics/skills` contents API, GitHub topic `claude-code-skill` / `agent-skills`.
3. For each hit, try to fetch `SKILL.md` (raw.githubusercontent.com or API contents). Keep name, description, url, stars, pushed_at, source_id.
4. Quality gate: SKILL.md (or `.agents/skills` / `.claude/skills` path) AND (stars ≥ 10 OR pushed in 180 days OR registry entry). Dedup by `full_name` / skill name.
5. Assign to stages (LLM or keyword overlap). Empty required stage → second-pass search with that stage's queries. Still empty → `{gap: true}`.
6. Cap 16 skills, but never drop the last skill of a stage to meet the cap. Completeness > cap.
7. Write package to `output/skills/<hash>/` : `index.json`, copied `SKILL.md` files, article, images dir.
8. LLM writes article from `docs/skill_finder/PACKAGE_ARTICLE.md`. Every skill name and `source_id` appears in body, stage order.

LLM missing → 502 `skill_search_failed` with stable error_code, no package.
