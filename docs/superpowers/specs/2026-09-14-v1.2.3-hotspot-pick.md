# AutoPosting 1.2.3 — 已选标题栏 + 左右多选高亮不同步

Controller-owned patch. Two grok-4.6 implementers. Do **not** bump version, restart 8080, or write PATCH/archives.

## Root cause (binding)

Hotspot lane has **two** highlight systems that currently look almost the same:

| Gesture | State | Class | Used by generate? |
|---|---|---|---|
| Click card body | `state.item` | `.hotspot-item.selected` | Only when `pickedIds` is empty |
| Click `.ht-title` | `state.pickedIds` | `.is-picked` | Yes — `generate()` sends `item_ids: pickedIdList()` whenever any pick exists |

`selectHotspot` never toggles off: clicking an already-`.selected` card keeps the gold. Favorites title-picks fill `pickedIds`. Then generate **ignores** the left focused card. User sees left still gold, cannot dismiss it, and the fused article does not contain that left title.

`togglePicked` + `syncPickedHighlights` are fine for true title-picks. The failure is focus gold masquerading as pick, plus no unfocus.

## Goal

1. Bottom-right of **热点候选** (`#hotspots-panel`) shows the titles that will actually go into 生成文章.
2. Left list + favorites mixed pick: unpicking / unfocusing left gold works; generate matches the dock.

## Generate set (do not change the payload rule)

- If `pickedIdList().length >= 1` → `item_ids` = that list only (not `state.item` unless it is also picked).
- Else → `item_id` = focused `state.item`.

The dock displays that same set: picks if any, otherwise the focused card title (one line, labeled so it is obvious it is 焦点 not 多选).

## Task A — focus vs pick (bug)

Own: `.hotspot-item.selected` CSS, `selectHotspot`, tests. Do **not** add `#picked-dock`. Do **not** change `find_skills`.

3. `syncPickedHighlights` stays the source of `.is-picked` on `#hotspot-list .hotspot-item` and `#favorites-list .fav-item`.
4. After `selectHotspot` / `clearHotspotSelection`, if `typeof renderPickedDock === "function"` call it (Agent B defines it; may be missing while you work).
5. Tests (INDEX_HTML string assertions, unique names):
   - `.hotspot-item.selected` rule does not copy the `.is-picked` gold fill (assert `is-picked` block still has the inset gold; `selected` still has `::before`).
   - `selectHotspot` contains a re-click unfocus path (`clearHotspotSelection` or `state.item = null` when clicking the active button).
   - `generate()` still uses `pickedIdList()` / `item_ids` when picks exist.
