## Requirements

### 1. 「收藏」button next to 设置

In `<header>`, immediately after `#config-btn`, add `<button type="button" id="favorites-btn">收藏</button>`.

### 2. One-click star on hotspot items

Each hotspot (and viewpoint) candidate gets a star control that toggles favorite without navigating away. Star state is independent of multi-select highlight.

Persist in SQLite (stdlib only), same pattern as `_ensure_skill_finder`:

```sql
CREATE TABLE IF NOT EXISTS hotspot_favorites (
  item_id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  summary TEXT NOT NULL DEFAULT '',
  payload_json TEXT NOT NULL,
  favorited_at TEXT NOT NULL
);
```

Store enough of the candidate dict in `payload_json` to re-render if the item later drops out of the current window.

APIs:

- `GET /api/favorites` → `{ok, items: [...]}` newest first
- `POST /api/favorites` `{item_id}` → save from current hotspot payload or `get_item`
- `DELETE /api/favorites` `{item_id}`

Never log secrets.

### 3. Title click multi-select with highlight

Clicking the article title (`.ht-title`, the original title span — not the whole card) toggles membership in a multi-select set. Selected rows use a clear highlight class (e.g. `.is-picked`). 

Card click outside the title may still set the focused item for 打开原文 / 找切口 (keep that). Multi-select set is what 「生成文章」uses when non-empty.

`generate-btn` enabled when the focused item exists **or** the picked set is non-empty.

### 4. Favorites drawer

`#favorites-btn` toggles a side drawer `#favorites-drawer`.

When open:

- `body.favorites-open` (or equivalent) **reflows the rest of the page** (main/content margin or grid shrinks by the drawer width). Not a modal that merely overlays without layout change.
- Closing restores layout.
- Drawer lists past favorites (title, summary, star to unfavorite, title click toggles the same multi-select set).

### 5. Multi-select spans list + drawer

`state.pickedIds` (or equivalent) is the union of picks from `#hotspot-list` and `#favorites-drawer`. Highlight both surfaces.

### 6. Fusion script, unchanged article prompt

When generating with 2+ picked item ids:

- New module `src/autoposting/article_fuse.py` with `fuse_hotspot_items(items: list[dict]) -> dict` producing **one** article-shaped payload: `title`, `content_text` (or `summary`), plus union of `source_ids` if present.
- Fusion concatenates the real items into one synthetic piece (clear per-source sections). It does not instruct the model how to write.
- `Workbench.generate_article` / `WebApp.articles` accept `item_ids: list[str]` (keep `item_id` for the single-item path).
- If `len(item_ids)==1` or only `item_id`: existing path, byte-stable behavior.
- If `len>=2`: fuse, then call the **existing** `llm_service.generate_article` / `build_article_prompt` with the fused title + fused content as if it were one item. **Do not** add fusion instructions to `docs/ARTICLE_BASE_PROMPT.md`, style files, or `build_article_prompt`.

JS `generate()`: if picked set size ≥ 1, send `item_ids` (sorted unique). If size ≥ 2, do not change `prompt_style`. If size == 0, keep current `state.item.item_id` behavior.
