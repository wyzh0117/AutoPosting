# Skill 查找覆盖地图

把用户的关键词或需求描述收成可执行目标，还原从 0 到交付的生产链，再拆成可检索模块。目标是完全涵盖，不是搜到几个热门结果就停。只输出一个 JSON 对象，不要发明 skill。

## 拆解规则

1. 理解需求：用一句话写出 `goal`（可附带读者/交付物）。做完这件事，使用者能从零产出到可交付。
2. 还原生产链：`chain` 从左到右、由浅入深，0 到交付。每项含 `id`、`name`、`role`（入口/准备/制作/装配/交付等）。
3. 工作流分解：列出 6–12 个模块（`stages`）。阶段按「从左到右、从上到下、由浅入深」排序：入口/选题 → 准备 → 核心制作 → 装配 → 发布/复盘。
4. 每个模块给 2–4 个检索词（中英都要），写入 `stages[].queries`，以及「没有该阶段就算覆盖失败」。
5. 不要把同一能力拆成两个阶段；不要只围绕最热的那个词打转。

## 检索词模板

每个阶段至少构造这些查询：

- `{stage} SKILL.md`
- `{stage} claude skill OR agent skill`
- `{query} {stage} site:github.com`
- `filename:SKILL.md {stage}`

## 质量门槛

收录必须同时满足：

- 能定位到 `SKILL.md`、`.agents/skills/`、`.claude/skills/` 或同等技能说明文件
- 热度或新鲜度至少一条：GitHub stars ≥ 10，或 180 天内有提交，或来自已知登记处的当前条目
- 说明文字能看出它解决哪个阶段，不是空壳 README
- 去重：同一仓库/同一 skill 名只留一条；fork 让给上游

## 补洞

第一轮按阶段归类后，任何空阶段必须再搜一轮，换检索词，直到该阶段至少 1 条合格技能。

仍为空的阶段必须保留在对外输出里：标记 `gap: true` 并给出短原因（默认「这一环没有找到合格 skill」），不要发明「缺口 skill」，不要在介绍文里写缺失阶段。展示给用户的 coverage 含全部阶段，其中 `gap: true` 表示这一环没找到合格 skill。

## 输出 JSON

只输出这个对象：

```
{"goal":"...","title":"...","theme":"...","chain":[{"id":"c1","name":"...","role":"..."}],"stages":[{"id":"...","name":"...","queries":["中文词","english term"],"required":true}]}
```
