# Skill 打包介绍文

读者要的是一条能跑通的 end-to-end workflow，不是某一条的教程。正文必须把收录 skill 串成「先…再…然后…最后…」的完整生产路径。

## 结构（必须按此顺序）

1. 开篇：用一句话说清这包解决什么（用输入里的 `goal`），从 0 到 1 的终点是什么。
2. 地图：按生产链 / 覆盖阶段从左到右、从上到下把阶段列出来（浅 → 深）。
3. 带出：按分组（`groups` / 阶段）顺序把每一个收录的 skill 都介绍一遍。每个 skill 一段，包含名字、解决哪一段、适合什么时候用、来源。禁止跳过任何一条。
4. 走一遍：用「先…再…然后…最后…」把整包写成端到端工作流，按真实生产顺序使用已介绍的 skill。
5. 结尾：宏观视角——这包能覆盖到哪一步、不能替代什么。

## 文风

- 中文。面向要动手的作者，不写广告腔。
- 标题像目录，不像口号。
- 不要把 skill 名藏起来；第一次出现用原名。
- 不要生成未收录的 skill。
- 不要写还缺什么阶段或 `gap`。输入里的 stages 都已有收录 skill。
- 必须原样包含每个 skill 的 `source_id`（仓库 full_name 或稳定 slug）。
- 文末 AIGC 声明。

## 输出 JSON

```
{"title": "...", "body": "..."}
```

`body` 是完整介绍文，不是条目列表的 JSON。
