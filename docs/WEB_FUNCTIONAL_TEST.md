## 3.2.0 新信息架构验收

按顺序走完，每步都要看到真实结果，不接受只看按钮存在。

### A. 顶栏与旧栏目退场

1. 打开 `http://127.0.0.1:8080/`，徽章应为 `v3.2.0 · 本地服务`。
2. 顶栏应只有：首页、资讯、资源、创作、发布、信息源、运行记录、设置，加右侧微信/小红书平台分段。
3. 页面里不应再出现「热点候选」「观点候选」「GitHub 周榜」「Skill查找器」页签；在页面源码里搜索 `legacy-lane-tabs` 应为 0 处。

### B. 资讯 → 研究

1. 点「资讯」，确认标题是「资讯探索」，说明为「按综合分、时效与独立来源聚合资讯事件」。
2. 点「刷新全部」，等待采集完成；列表出现 Event Cluster，卡片应显示独立来源数与内容数。
3. 点击「X 个独立来源」应展开来源明细；选中一个或多个事件后点「研究已选事件」，研究页应出现可恢复的 Dossier。

### C. 资源探索（自然语言 + Preset）

1. 点「资源」，输入「帮我找能自动做 PPT 的 Agent Skill / Repo」，勾选 Repo + Skill + Web，点「搜索资源」。
2. 结果卡片应包含：ResourceSet 状态、来源状态（每个 adapter 的 status/count）、候选（类型、客观分、推荐标记）。若某个来源失败，应显示降级提示与诊断，而不是「暂无内容」。
3. 点「GitHub Weekly Preset」，结果 query 应为「本周 AI 新项目」，preset 为 `github_weekly`，候选以 Repo 为主。
4. 刷新页面后点「资源」再查 `GET /api/resources?limit=20` 对应的列表（或直接看最近一次结果），持久化的 ResourceSet 应能回读。

### D. 创作页出图工作台

1. 点「创作」，应能看到「GitHub 周榜出图工作台」和「Skill 海报出图工作台」两块（不再依赖旧栏目切换）。
2. 在资源页点「周榜出图工作台」（或直接到创作页点「抓取本周周榜」），抓取完成后画廊应出现 3:4 封面与项目卡；点「生成图片」应真的产出 PNG 并可导出。
3. 在资源页输入 Skill 需求或粘贴 skill 链接后点「送入 Skill 出图」，页面应跳到创作页，Skill 工作台显示收录列表与介绍文；点「生成图片」应产出封面 + 每个 skill 一张海报。

### E. 发布中心

1. 先在创作页生成一篇稿（需要文章模型；没有模型时用已有草稿）。
2. 点「发布」，应列出草稿卡片：标题、平台、状态（待审批/已审批）、更新时间、最近发布尝试。
3. 点草稿的「继续编辑」应载入创作页对应草稿；点「到草稿箱」（微信）或「生成发布包」（小红书）应分别得到草稿箱写入结果或本地包路径，安全边界与旧流程一致。
4. 点「定时到草稿」应跳到创作页并聚焦定时输入框。

### F. 信息源与运行记录

1. 点「信息源」，顶部统计（总源/启用/停用/正常/异常）与实际开关一致，切换开关后刷新仍保留。
2. 点「运行记录」，应看到最近 Collection Run 的尝试/成功/失败源数、抓取量、去重后数量；点一条运行应展开本次抓取的源明细。

### G. 设置集中化

1. 点「设置」，文章/翻译/聊天/榜单模型、GitHub Token、微信公众号、小红书账号都在这里配置。
2. 保存 GitHub Token 后应只显示「已配置」，不回显明文；清空后回落环境变量。

## 步骤

### 1. 打开首页

1. 浏览器打开 `http://127.0.0.1:8080/`。
2. 顶栏徽章应为 `v1.3.1 · 本地服务`。
3. 品牌栏正下方应有全宽 `<nav id="app-nav">`：左侧四个栏目（热点候选 / 观点候选 / GitHub 周榜 / Skill查找器），右侧微信 / 小红书。进度条在导航下方文档流里，不要盖住按钮。
4. 左栏主区应立刻出现话题/新闻卡片（或明确的空状态说明），不必先点「刷新全部」。
5. 卡片应在订阅源列表**上面**。底部只有一行「N 路抓取成功 · 点开看来源」，默认收起。

通过标准：打开页面 2 秒内能看到候选标题，或看到「当前时间范围内没有话题或新闻」。四个栏目和两个平台都在页顶，不在左栏标题里。

### 2. 看清「抓取成功」和「只刷这个」

1. 点底部来源行，展开订阅列表。
2. 读说明：这些不是新闻。「抓取成功」= 这个订阅上次拉 RSS 没报错；「只刷这个」= 只重新抓这一路。
3. 对照圆点：绿=抓取成功，红=抓取失败，黄=该刷新了，灰=还没抓过或已停用。

通过标准：能分清「订阅健康」和「热点候选」。

### 3. 刷新全部

1. 保持默认 4 小时（或当前已自动拉长的窗口）。
2. 点「刷新全部」。
3. 抓取过程中，已有候选必须仍留在列表里，状态类似「正在从各订阅源抓取，已有候选会留在上面…」。
4. 结束后状态出现「共 N 条候选」，可带「新入库」或「个源失败」。
5. 若近 4 小时为空，页面应自动改看 6/24 小时并写明原因。

通过标准：刷新中和刷新后都能看见话题卡片，或看见改看更长时间窗的说明。看不到「只有一排站点名、没有新闻」。

### 4. 时间范围和排序

1. 把时间范围改成 24 小时，卡片应更新且不整页卡死。
2. 切到「时间优先」，第一条应变新。
3. 切回「热度优先」，来源数多或讨论量大的应靠前。

通过标准：切换后列表有标题，状态条更新条数。

### 5. 单源刷新

1. 展开底部来源。
2. 点某一个启用源的「只刷这个」。
3. 其它源的上次时间不应被这次请求清掉；状态提到「正在刷新该源」。

通过标准：按钮恢复，列表仍在。

### 6. 清空再配置文章模型

1. 点「设置」→「模型」。
2. 若「已保存接口」里有旧接口，点删除并确认。
3. 清空「接口地址」和「API Key」。
4. 填入本文件「测试用模型接口」中的地址和 Key。
5. 点「连接并拉取模型」。
6. 文章模型选列表里的一个（本次实测是 `deepseek-v4-flash` / `deepseek-v4-pro`，不一定有 `deepseek-chat`），Effort 保持 `none`，点「用于文章」。
7. 点「保存」或「关闭」。
8. 若英文候选仍显示未翻译，可点「翻译标题」。

通过标准：提示「已设为文章模型」；文章区模型下拉出现刚选的模型名。

### 7. 选一条候选，生成微信稿

1. 点左栏第一条有标题的候选，「生成文章」应变可点。
2. 确认平台是「微信」，点「生成文章」。
3. 等待生成结束。

通过标准：右侧出现标题和正文；正文开头有 `【信息来源 N 条 · 原文 M 篇】`；文末尽量有原文链接；有 AIGC 声明。若有配图，预览区出现。

### 7b. 找切口（有社会电荷的候选才测）

1. 选中一条后，「找切口」可点。「生成文章」仍可在未找切口时直接点。
2. 点「找切口」，等待列表。
3. 若出现卡片：勾选两张（先勾主切口），再生成。标题应跟第一张，开头含两张；争议表述为公开报道。
4. 换一条无电荷候选：提示「未发现可用切口」，仍可生成。

通过标准：不点找切口的生成与以前相同；勾选后的稿按切口起笔。

### 8. 配图和放大（有图才测）

1. 点一张缩略图，应弹出大图。
2. 若多于一张，点「上一张 / 下一张」。
3. 点关闭或大图本身关掉灯箱。
4. 默认只有封面勾选、正文未勾选。勾选/取消「封面」「正文」，正文勾选后点「上移 / 下移」，选择应留下。
5. 点「重新扫描」，列表不应崩。

通过标准：灯箱能开能关；选择变化后卡片标记跟着变。无图则记「本条无配图」，不算失败。

### 9. 改稿并保存

1. 标题末尾加「（验收）」。
2. 正文保留来源 ID 和 AIGC 声明，改一句非关键描述。
3. 点「保存修改」。

通过标准：状态成功；刷新文章区后改动还在。

### 10. 清空再配置对话模型

1. 再开设置 → 模型。
2. 清空地址和 Key（不要点选用旧接口来带出地址）。
3. 重新填入同一组 DeepSeek 地址和 Key。
4. 连接并拉取模型。
5. 对话模型选列表里的一个（与文章相同即可），点「用于对话」。
6. 关闭设置。

通过标准：提示「已设为对话模型」；右下角对话模型下拉可用。

### 11. 对话框

1. 输入「用一句话复述刚才这篇稿的主题」，发送。
2. 应出现用户气泡和模型回复。
3. 页面应向下伸长，而不是把左栏候选挤没。

通过标准：有模型回复，候选列表仍在。

### 12. 写作风格

1. 设置 → 写作风格。
2. 填「用短句，少形容词，保留某某称。」
3. 保存并关闭。
4. 再清空并重填模型地址和 Key，重新「用于文章」（本步专门测风格保存后模型仍可用）。
5. 换平台到「小红书」，对同一条或另一条候选再生成一次。

通过标准：小红书稿生成成功；风格要求应进入这次生成（不必逐字核对模型是否听话，但请求不得报「未配置模型」）。

### 13. 账号页（不发、不填 X）

1. 设置 → 账号 → 微信：确认 App ID / Secret 为空时可看到未配置提示。不要填真实凭据去写草稿箱。
2. 小红书：账号名称可填「验收号」，创作中心保持官方页。
3. X：只确认有 Bearer 输入框；已配置时只显示状态和「删除配置」，**不要填 token，不要测 X 抓取**。

通过标准：三个子页能切换；微信仍显示未配置。

### 14. 定时发布控件（不真正发布）

1. 回到已生成的稿。
2. 确认「定时到草稿」和「到草稿」按钮可用。
3. 填一个未来时间，但**不要点到草稿**。点定时到草稿可以，用于确认预约写入；不要走微信 live。

通过标准：按钮不是永久灰的。若点了定时到草稿，状态应说明已预约或缺配置。不要做成功的微信 live 写入。

### 15. 收尾

1. 硬刷新页面。
2. 候选仍应从数据库列出。
3. 已保存的模型接口应还在；进程内微信凭据应仍未配置。
4. 关掉设置。

### 16. 顶栏切到 GitHub 周榜

1. 点顶栏「GitHub 周榜」。
2. 左栏应变为仓库列表控件，右栏为 3 列 3:4 画廊。
3. 预览封面卡 `.gh-cover` 与项目海报 `.gh-poster` 都应为 3:4（1080×1440）；只有小红书纸卡 `.xhs-paper` 仍是 9:16 手写纸比例。

通过标准：栏目切换只改左右栏内容，顶栏平台分段仍在。

### 17. Skill查找器

1. 点顶栏「Skill查找器」。
2. 左栏出现关键词输入和「查找」，「查找」两字同一行、不被裁切；其下是「粘贴 skill 链接」一行和折叠的「GitHub Token（可选）」。不再显示时间范围、刷新全部、翻译、找切口、生成文章。
3. 右侧上方应立刻看到工具栏 + `#skills-gallery` 画廊，`#skills-article` 介绍文在画廊**下方**（1.3.0 起），介绍文自带滚动条、不会被 3:4 画廊顶出视野；空态是「查找完成后会生成介绍文」。
4. 输入一个短需求（不要用「AI制作短剧工作流」做现场检索也可以），点查找。
5. 等待条没有滑动 meter；有「停止」。查找中应看到「第 n/7 步」和当前步骤名（理解需求 → … → 组合工作流），已用时间在走。点停止应中断。
6. 若未配置文章模型，应看到稳定失败而不是空白死页。
7. 若已配置模型：七步走完；左侧 skill 应先出现；介绍文是 end-to-end 工作流；全部 skill 展示完后再出图。**没找到合格 skill 的环节必须可见**（灰色虚线 chip「阶段名 · 没找到合格 skill」+ 汇总说明），不能被静默删掉；这两条说明只在第四栏出现。出图不得把介绍文覆盖成空白。

通过标准：第四栏可进可出；「查找」两字一行；等待条能看出在干活也能停；成功时先列表后图片，介绍文按生产顺序串 skill；缺口与降级说明切到别的栏目就看不见。

### 19. Skill查找器：粘贴链接与 GitHub Token（1.3.1 新增）

1. 在第四栏粘贴一个真实 skill 链接（例：`https://github.com/anthropics/skills/tree/main/skills/web-artifacts-builder`；注意这个仓库的技能在 `skills/` 子目录下），点「加入」或按回车。
2. 应看到：输入框清空；skill 列表多出该 skill；介绍文被重写并点名该 skill（没配模型时用机械清单兜底）；画廊先铺「排队中」占位，然后自动出图。
3. 出图完成后应有「封面 + 每个收录 skill 一张」；打开新建技能的 `*.html`，四个板块（做什么 / 如何实现 / 适合哪些人群 / 使用场景）都要有内容，页脚张数等于包内张数。
4. 再粘贴同一个链接：不应出现第二份，只替换原来那条。
5. 同一个仓库的两个 skill 目录（monorepo，例如 `.../tree/main/skills/web-artifacts-builder` 和 `.../tree/main/skills/canvas-design`）一起粘贴：两条都要进包，不能被当成重复。
6. 粘贴没法识别的内容（`https://gitlab.com/a/b`、纯中文）：应提示「没有识别到 skill 链接」或列出跳过条数，页面不报错。
7. 查找进行中粘贴：应提示「查找还在进行，等它结束再粘贴」。
8. 展开「GitHub Token（可选）」，粘一个 token 保存：状态变成「已配置 GitHub Token…」；刷新页面仍是已配置；任何接口响应里都不应出现 token 明文。点「清除」后回到未配置。
9. 找一次会限流的检索（或断开网络）：说明文案应是中文（「GitHub 接口限流…」/「GitHub 连不上」等），不是 `github:RuntimeError` 这种记号；原始记号只在该行的 tooltip 里。

通过标准：粘贴 = 和检索到的一样走完「简介 + 海报」；重复不翻倍、monorepo 不吞兄弟；token 只进钥匙串、不回显；降级说明说人话。

### 18. 热点收藏与多选融合

1. 顶栏「设置」旁有「收藏」。点开后右侧弹出收藏抽屉，主栏应变窄，不是只盖一层遮罩。
2. 热点卡片右上角有星标，可一键收藏；抽屉里能看到刚收藏的标题。
3. 点击候选**标题**（不是整张卡片）应出现 `.is-picked` 金底，页面右下角固定 `#picked-dock` 出现「已选 N」。滚动页面时已选栏仍在视口右下。卡片单击只是焦点（左侧细条），再点同一张卡片应取消焦点。
4. 抽屉里点标题加入同一组多选；每条有「打开原文」。左栏焦点未点标题的，不应进已选栏。再点左栏标题可取消 `.is-picked`，已选栏同步少一条。
5. 多选 ≥2 后点「生成文章」：仍走原来的文章 prompt，正文是已选栏那些篇的融合。不要改写作风格下拉。点已选芯片应能取消该篇。

通过标准：开合抽屉页面会让位；星标与多选独立；已选栏与生成用的篇目一致；焦点金底不再冒充多选。

## 失败时记什么

- 徽章版本、时间范围、左栏是不是只有来源行没有卡片
