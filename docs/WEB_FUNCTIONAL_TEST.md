## 3.2.1 新信息架构验收

按顺序走完，每步都要看到真实结果，不接受只看按钮存在。

### A. 顶栏与旧栏目退场

1. 打开 `http://127.0.0.1:8080/`，徽章应为 `v3.2.1 · 本地服务`。
2. 顶栏应只有：首页、资讯、资源、创作、发布、信息源、运行记录、设置，加右侧微信/小红书平台分段；对应 `data-app-page` 为 `home|news|resources|creation|publishing|sources|runs|settings`。「事件研究」页（`data-app-page="research"`）不在顶栏，只能从资讯页的「研究已选事件」进入，页内有「返回资讯」。
3. 页面里不应再出现「热点候选」「观点候选」「GitHub 周榜」「Skill查找器」页签，也不应出现找切口、相关搜索补充抽屉与旧 Skill 查找器的 DOM：在页面源码里搜索 `#find-hooks-btn`、`#hook-list`、`#related-search-btn`、`#news-supplement-`、`#skill-search-row`、`#skill-source-bar`、`#skill-degraded-note`、`#skill-list`、`#github-list` 都应 0 处；`[data-lane]`（以及 `legacy-lane-tabs`、`body.lane-`）也应 0 处。
4. 新界面应真实存在：资讯工具栏的「来源范围」`#news-scope-select`（全部来源 / 仅订阅源 / 仅社区来源）、研究页的 `#research-to-creation-btn`（进入创作，有 Dossier 前是灰的）、创作页的 `#article-context` 横幅与 `#article-context-clear`、Skill 工作室的 `#skills-sources`（`#skills-source-chips`、`#skills-degraded-note`）。
5. 徽章版本以 `v3.2.1` 为准（`GET /api/status` 的 `version` 也应为 `3.2.1`）。

### B. 资讯 → 研究

1. 点「资讯」，确认标题是「资讯探索」，说明为「按综合分、时效与独立来源聚合资讯事件」。
2. 点「刷新全部」，等待采集完成；列表出现 Event Cluster，卡片应显示「N 个来源」以及时间、来源等级、热度等元信息；把「来源范围」切到「仅社区来源」再刷新，列表应只剩社区来源（本机若没启用社区源则应给空列表说明，而不是照旧显示订阅源）；切回「全部来源」应恢复。
3. 点每张卡片右侧的方框按钮（`aria-label`「加入已选（可多篇融合生成）」）勾选一个或多个事件，「研究已选事件」应变可点（卡片点击本身只是焦点，不进多选；没有 `event_id` 的候选点了也不会让研究按钮变亮，挑卡片上带事件元信息的那类）。点「研究已选事件」后页面切到「事件研究」，应看到状态 / 事件 / 主题 / 证据 / 降级五个统计卡、证据清单与诊断；`GET /api/research?limit=20` 与 `GET /api/research/{dossier_id}` 能回读这份 Dossier（页面刷新后不会自动恢复上次研究，要重新研究）。

### B2. 事件研究 → 进入创作 → 生成文章（3.2.1 正式链路）

1. 在资讯页用卡片右侧的方框按钮勾选一个事件（`#picked-dock` 显示「已选 1」），点「研究已选事件」，等研究完成（研究页出现五个统计卡与证据清单，状态行显示「研究完成 · …」，降级时会写明「部分能力降级」）。
2. 研究页点「进入创作」：页面应跳到创作，文章区顶部出现 `#article-context` 横幅，标题是这次 Dossier 的标题，副文写明来源类型/证据条数等信息；此时**不选任何候选**，「生成文章」也应是可点的。
3. 确认风格下拉（AI专家 / 经验分享 / klinkenborg_style）与文章模型已配好，点「生成文章」。通过标准（点出来的，不是读 DOM）：右侧出现标题和正文；正文含 `AIGC` 声明；每个来源 ID 出现在第一次引用／转述该来源的位置，能解析到原文 URL 的来源会在该位置直接变成原文链接（形如 `https://…`，不是文末「来源清单」尾注）；文章区 `#article-sources` 列出本次来源 ID。
4. 点 `#article-context-clear` 清除上下文，状态行应说明已回到手动选材；再选候选生成时走的是旧的手动路径（不读 Dossier）。
5. 负向检查：带上 `#article-context` 后生成，不应再触发任何新检索（等待条里不出现找切口或相关搜索的步骤）；用 curl 传一个不存在的 `dossier_id`（`POST /api/articles`）应返回 400，`error_type` 为 `ArticleContextError`、`error` 是 `dossier_not_found` 一类的稳定码、`error_reason` 是中文原因；页面上引用了失效 Dossier 时点「生成文章」应显示中文原因而不是空白。

### C. 资源探索（自然语言 + Preset）

1. 点「资源」，输入「帮我找能自动做 PPT 的 Agent Skill / Repo」，勾选 Repo + Skill + Web，点「搜索资源」。
2. 结果卡片应包含：ResourceSet 状态、来源状态（每个 adapter 的 status/count）、候选（类型、客观分、推荐标记）。若某个来源失败，应显示降级提示与诊断，而不是「暂无内容」。
3. 点「GitHub Weekly Preset」，结果 query 应为「本周 AI 新项目」，preset 为 `github_weekly`，候选以 Repo 为主。
4. 刷新页面后点「资源」再查 `GET /api/resources?limit=20` 对应的列表（或直接看最近一次结果），持久化的 ResourceSet 应能回读。

### D. 创作页出图工作台

1. 点「创作」，应能看到「GitHub 周榜出图工作台」和「Skill 海报出图工作台」两块（不再依赖旧栏目切换）。
2. 在资源页点「周榜出图工作台」（或直接到创作页点「抓取本周周榜」），抓取完成后画廊应出现 3:4 封面与项目卡；点「生成图片」应真的产出 PNG 并可导出。
3. 在资源页输入 Skill 需求或粘贴 skill 链接后点「送入 Skill 出图」，页面应跳到创作页，Skill 工作台显示收录列表与介绍文；点「生成图片」应产出封面 + 每个 skill 一张海报。

### E. 发布中心

1. 先在创作页生成一篇稿（需要文章模型；没有模型时用已有草稿）。
2. 点「发布」，应列出草稿卡片：标题、平台、状态（待审批/已审批）、更新时间、最近发布尝试。
3. 点草稿的「继续编辑」应载入创作页对应草稿；点「到草稿箱」（微信）或「生成发布包」（小红书）应分别得到草稿箱写入结果或本地包路径，安全边界与旧流程一致。
4. 点「定时到草稿」应跳到创作页并聚焦定时输入框。

### F. 信息源与运行记录

1. 点「信息源」，顶部统计（总源/启用/停用/正常/异常）与实际开关一致，切换开关后刷新仍保留。
2. 点「运行记录」，顶部应显示运行记录条数、最近状态、成功源 / 失败源数与去重后条数；点一条运行应把下方列表换成该次运行的源级明细（每个源一行：状态、抓到条数、诊断/报错），点另一条应能切换。

### G. 设置集中化

1. 点「设置」，文章/翻译/榜单模型、写作风格、GitHub Token、微信公众号、小红书账号、X 读取令牌都在这里配置（GitHub Token 只在这一处，创作页不再有第二个输入框）。
2. 保存 GitHub Token 后应只显示「已配置」，不回显明文；清空后回落环境变量。
3. 设置里没有「聊天模型」页签，也没有聊天输入框：聊天只剩 API（`POST /api/chat/model`、`POST /api/chat`），见步骤 10。

## 步骤

### 1. 打开首页

1. 浏览器打开 `http://127.0.0.1:8080/`。
2. 顶栏徽章应为 `v3.2.1 · 本地服务`。
3. 品牌栏正下方应有全宽 `<nav id="app-nav">`：左侧八个栏目（首页 / 资讯 / 资源 / 创作 / 发布 / 信息源 / 运行记录 / 设置），右侧微信 / 小红书。进度条在导航下方文档流里，不要盖住按钮。
4. 首页主区是探索输入框（`#home-query` + 「开始探索」）、右侧「最近活动」和三个快捷卡片（资讯探索 / 资源探索 / 继续创作）；点「打开资讯」应切到资讯页并看到话题/新闻卡片或明确的空状态说明，不必先点「刷新全部」。
5. 候选卡片在资讯页订阅源列表**上面**。页面底部只有一行「N 路抓取成功 · 点开看来源」，默认收起。

通过标准：打开首页能看清下一步入口，进资讯 2 秒内能看到候选标题或看到「当前时间范围内没有话题或新闻」。八个栏目和两个平台都在页顶。

### 2. 看清「抓取成功」和「只刷这个」

1. 点底部来源行，展开订阅列表。
2. 读说明：这些不是新闻。「抓取成功」= 这个订阅上次拉 RSS 没报错；「只刷这个」= 只重新抓这一路。
3. 对照圆点：绿=抓取成功，红=抓取失败，黄=该刷新了，灰=还没抓过或已停用。

通过标准：能分清「订阅健康」和「资讯候选」。

### 3. 刷新全部

1. 保持默认 4 小时（或当前已自动拉长的窗口）。
2. 点「刷新全部」。
3. 抓取过程中，已有候选必须仍留在列表里，状态类似「正在从各订阅源抓取，已有候选会留在上面…」。
4. 结束后状态出现「共 N 条候选」，可带「新入库」或「个源失败」。
5. 若近 4 小时为空，页面应自动改看 6/24 小时并写明原因。

通过标准：刷新中和刷新后都能看见话题卡片，或看见改看更长时间窗的说明。看不到「只有一排站点名、没有新闻」。

### 4. 时间范围和排序

1. 把时间范围改成 24 小时，卡片应更新且不整页卡死。
2. 切到「时间优先」，第一条应变新。
3. 切回「热度优先」，来源数多或讨论量大的应靠前。

通过标准：切换后列表有标题，状态条更新条数。

### 5. 单源刷新

1. 展开底部来源。
2. 点某一个启用源的「只刷这个」。
3. 其它源的上次时间不应被这次请求清掉；状态提到「正在刷新该源」。

通过标准：按钮恢复，列表仍在。

### 6. 清空再配置文章模型

1. 点「设置」→「模型」。
2. 若「已保存接口」里有旧接口，点删除并确认。
3. 清空「接口地址」和「API Key」。
4. 填入本文件「测试用模型接口」中的地址和 Key。
5. 点「连接并拉取模型」。
6. 文章模型选列表里的一个（本次实测是 `deepseek-v4-flash` / `deepseek-v4-pro`，不一定有 `deepseek-chat`），Effort 保持 `none`，点「用于文章」。
7. 点「保存」或「关闭」。
8. 若英文候选仍显示未翻译，可点「翻译标题」。

通过标准：提示「已设为文章模型」；文章区模型下拉出现刚选的模型名。

### 7. 选一条候选，生成微信稿

1. 在资讯页点第一条有标题的候选选中它（「打开原文」应变可点）；切到「创作」，「生成文章」也应可点（选中状态跨页保留，候选列表本身在资讯页）。
2. 确认文章区顶部没有 `#article-context` 研究横幅（有就点 `#article-context-clear` 清掉，否则会走 Dossier 而不是这条候选）。
3. 确认平台是「微信」，点「生成文章」。
4. 等待生成结束。

通过标准：右侧出现标题和正文；正文含 `AIGC` 声明；来源 ID 出现在第一次引用／转述该来源的位置，能解析到 URL 的来源已就地变成原文链接（页面不再加 `【信息来源 N 条 · 原文 M 篇】` 表头或文末「原文链接」清单）；若有配图，预览区出现。

### 7b. 找切口已删除（负向检查）

1. 资讯页与创作页都不应出现「找切口」按钮，页面源码里 `#find-hooks-btn` 与 `#hook-list` 应为 0 处。
2. 选中候选后直接点「生成文章」即可；文章素材只来自 Topic Dossier 或已选 item，创作页不会再现场搜索。

通过标准：找不到找切口入口，也不需要它；生成路径与步骤 7 一致。

### 8. 配图和放大（有图才测）

1. 点一张缩略图，应弹出大图。
2. 若多于一张，点「上一张 / 下一张」。
3. 点关闭或大图本身关掉灯箱。
4. 默认只有封面勾选、正文未勾选。勾选/取消「封面」「正文」，正文勾选后点「上移 / 下移」，选择应留下。
5. 点「重新扫描」，列表不应崩。

通过标准：灯箱能开能关；选择变化后卡片标记跟着变。无图则记「本条无配图」，不算失败。

### 9. 改稿并保存

1. 标题末尾加「（验收）」。
2. 正文保留来源标记（来源 ID，或已被内联替换的原文链接）和 AIGC 声明，改一句非关键描述。
3. 点「保存修改」。

通过标准：状态成功；刷新文章区后改动还在。

### 10. 对话模型与对话（只剩 API）

1. 设置面板里不应有「聊天模型 / 用于对话」页签（模型页只有文章、翻译、榜单三个入口），页面里也没有聊天输入框。
2. 用 curl 配一次对话模型；`"model"` 换成步骤 6 实测可用的型号（配错型号会返回连通性校验失败）：
   `curl -X POST http://127.0.0.1:8080/api/chat/model -H 'Content-Type: application/json' -d '{"model": "deepseek-v4-flash", "base_url": "https://api.deepseek.com", "api_key": "sk-REPLACE-ME"}'`
3. 再用 curl 发一条消息：
   `curl -X POST http://127.0.0.1:8080/api/chat -H 'Content-Type: application/json' -d '{"messages": [{"role": "user", "content": "用一句话说明什么是 RSS"}]}'`

通过标准：第 2 步返回 `ok: true` 与 `chat_llm`；第 3 步返回模型回复文本。界面不提供对话框，聊天记录不写入 SQLite。

### 11. 对话框已移除（负向检查）

1. 创作页与资讯页都不应有聊天输入框或对话气泡区域：页面源码里搜索 `api("/api/chat"` 应为 0 处（前端不再调用聊天接口），`/api/chat` 只出现在服务端路由与请求体上限判断里。
2. 聊天能力只在 API 层（`POST /api/chat/model`、`POST /api/chat`），由步骤 10 覆盖。

通过标准：工作台没有聊天 UI，也不因缺聊天 UI 影响文章生成。

### 12. 写作风格

1. 设置 → 写作风格。
2. 填「用短句，少形容词，保留某某称。」
3. 保存并关闭。
4. 再清空并重填模型地址和 Key，重新「用于文章」（本步专门测风格保存后模型仍可用）。
5. 换平台到「小红书」，对同一条或另一条候选再生成一次。

通过标准：小红书稿生成成功；风格要求应进入这次生成（不必逐字核对模型是否听话，但请求不得报「未配置模型」）。

### 13. 账号页（不发、不填 X）

1. 设置 → 账号 → 微信：确认 App ID / Secret 为空时可看到未配置提示。不要填真实凭据去写草稿箱。
2. 小红书：账号名称可填「验收号」，创作中心保持官方页。
3. X：只确认有 Bearer 输入框；已配置时只显示状态和「删除配置」，**不要填 token，不要测 X 抓取**。

通过标准：三个子页能切换；微信仍显示未配置。

### 14. 定时发布控件（不真正发布）

1. 回到已生成的稿。
2. 确认「定时到草稿」和「到草稿」按钮可用。
3. 填一个未来时间，但**不要点到草稿**。点定时到草稿可以，用于确认预约写入；不要走微信 live。

通过标准：按钮不是永久灰的。若点了定时到草稿，状态应说明已预约或缺配置。不要做成功的微信 live 写入。

### 15. 收尾

1. 硬刷新页面。
2. 候选仍应从数据库列出。
3. 已保存的模型接口应还在；进程内微信凭据应仍未配置。
4. 关掉设置。

### 16. 创作页 GitHub 周榜出图工作台

1. 顶栏没有「GitHub 周榜」页签。点「资源」→「周榜出图工作台」，应跳到创作页并读取上次周榜快照（也可直接到创作页 `#github-studio` 点「抓取本周周榜」）。
2. 创作页应看到抓取控件、生成图片按钮、暗色/浅色与主色/副色/强调色控件，以及 3 列 3:4 画廊。
3. 预览封面卡 `.gh-cover` 与项目海报 `.gh-poster` 都应为 3:4（1080×1440）；只有小红书纸卡 `.xhs-paper` 仍是 9:16 手写纸比例。

通过标准：周榜出图只在创作页；点「生成图片」逐张产出 PNG（等待条显示「第 n / N 张」），勾选后可导出。

### 17. Skill 海报出图工作台（检索入口在资源页）

1. 顶栏没有「Skill查找器」页签。点「资源」，输入一个短需求并勾选 Skill，点「搜索资源」；或直接把需求交给「送入 Skill 出图」。
2. 点「送入 Skill 出图」应跳到创作页 `#skills-studio`：顶部是「读取上次收录 / 清空收录 / 去资源探索」，下面是 `#skills-sources`（每个来源一颗 chip）与 `#skills-gallery` 画廊，`#skills-article` 介绍文在画廊**下方**（自带滚动条，空态是「查找完成后会生成介绍文」）。
3. 检索中等待条没有滑动 meter；有「停止」。应看到「第 n/4 步 · 步骤名」（整理关键词 → 抓取来源 → 按工作流归组 → 汇总打包）和已用时间；点停止应中断。
4. 检索**不自动出图**：结束后画廊先铺「排队中」占位，点「生成图片」才逐张产出封面 + 每个 skill 一张海报。介绍文应点名收录的 skill（没配模型时用机械清单兜底），出图不得把介绍文覆盖成空白。
5. 若某个来源没返回：`#skills-degraded-note` 应显示中文降级说明（原始 `degraded_reasons` 记号只在该行 tooltip 里），`#skills-source-chips` 仍列出有结果的来源并可按来源全选/取消，不能静默丢结果。

通过标准：查找在资源页发起、出图在创作页完成；等待条能看出在干活也能停；来源与降级说明在工作室里直接可见。

### 19. Skill 粘贴链接与 GitHub Token

1. 在资源探索页的「粘贴 Skill 链接」文本框（`#resource-pasted-text`，占位文案「可选：粘贴 GitHub / skills.sh Skill 链接，加入同一组候选」）里贴一个真实 skill 链接（例：`https://github.com/anthropics/skills/tree/main/skills/web-artifacts-builder`；注意这个仓库的技能在 `skills/` 子目录下），点「送入 Skill 出图」。
2. 应看到：页面跳到创作页、工作室收录该 skill；介绍文被重写并点名该 skill（没配模型时用机械清单兜底）；粘贴路径会自动出图（画廊先铺「排队中」占位，随后逐张产出）。
3. 出图完成后应有「封面 + 每个收录 skill 一张」；打开新建技能的 `*.html`，四个板块（做什么 / 如何实现 / 适合哪些人群 / 使用场景）都要有内容，页脚张数等于包内张数。
4. 再粘贴同一个链接：不应出现第二份，只替换原来那条。
5. 同一个仓库的两个 skill 目录（monorepo，例如 `.../tree/main/skills/web-artifacts-builder` 和 `.../tree/main/skills/canvas-design`）一起粘贴：两条都要进包，不能被当成重复。
6. 粘贴没法识别的内容（`https://gitlab.com/a/b`、纯中文）：应提示「没有识别到 skill 链接」或列出跳过条数，页面不报错。
7. 检索进行中粘贴：应提示「查找还在进行，等它结束再粘贴」。
8. 到设置页的 GitHub Token 卡片（`#settings-github-token` + 「保存」/「清除」，创作页没有第二个 Token 输入框）：粘一个 token 保存，状态应变成「已配置（Token 不回显）」；刷新页面仍是已配置；任何接口响应里都不应出现 token 明文。点「清除」后回到未配置。
9. 找一次会限流的检索（或断开网络）：说明文案应是中文（「GitHub 接口限流…」/「GitHub 连不上」等），不是 `github:RuntimeError` 这种记号；原始记号只在该行的 tooltip 里。

通过标准：粘贴 = 和检索到的一样走完「简介 + 海报」；重复不翻倍、monorepo 不吞兄弟；token 只进钥匙串、不回显；降级说明说人话。

### 18. 热点收藏与多选融合

1. 顶栏「设置」旁有「收藏」。点开后右侧弹出收藏抽屉，主栏应变窄，不是只盖一层遮罩。
2. 热点卡片右上角有星标，可一键收藏；抽屉里能看到刚收藏的标题。
3. 卡片右侧的方框按钮（`aria-label` 为「加入已选（可多篇融合生成）」）点一下变金底 `.is-picked`，页面右下角固定 `#picked-dock` 出现「已选 N」；再点方框应变回「移出已选」并取消金底。滚动页面时已选栏仍在视口右下。
4. 点卡片主体（包括标题）是**焦点**而不是多选：左侧出现细条 `.selected`，`#picked-dock` 的「焦点」芯片跟着变；再点同一张卡片取消焦点。焦点不写进已选栏。
5. 收藏抽屉里的条目走同一个方框按钮加入多选，每条有「打开原文」。多选 ≥2 后切到创作页（确认 `#article-context` 是隐藏的，否则会走 Dossier）点「生成文章」：仍走原来的文章 prompt，正文是已选栏那些篇的融合。不要改写作风格下拉。点 `#picked-dock` 里已选的芯片应能取消该篇。

通过标准：开合抽屉页面会让位；星标与多选独立；多点一下方框就能进出多选、已选栏与生成用的篇目一致；焦点金底不冒充多选。

## 失败时记什么

- 徽章版本、时间范围、资讯页是不是只有来源行没有卡片
- 状态条原文
- 设置页报错原文（不要把 API Key 再抄到别处）
- 生成失败时的 `error_code` / `error_reason`；走 Dossier 时另记 `error_type`（预期 `ArticleContextError`）与 `dossier_id`
